# In-memory encrypted Source state

This owner-side module backs up the actual Source AEAD key and ORIGINAL Ckey
salt. Its only output is a fixed488-byte encrypted in-memory record. It owns no
filesystem writer, OS vault, credential discovery, network client, Vault phase,
SQL admission, proof receipt or finalized-head selection.

| Direct owner/dependency | Responsibility |
| --- | --- |
| [SourceOwner](../../source.rs) | Actual key/salt custody and full supplied RawBundle load/AEAD/index validation |
| [compact-store Owner](../../../../../compact-store/src/crypto.rs) | Guarded actual sealer reconstructed from explicit caller-owned key; no getter |
| [compact-query storage](../../../../../compact-query/src/storage.rs) | Complete image, TableId and private index binding |
| [Source commitments](../../../../../registry200-proof/src/source/commitment.rs) | Unchanged exact Ckey and canonical Gold field encoding |
| chacha20poly1305=0.10.1 | Existing pinned XChaCha20Poly1305 AEAD implementation |
| getrandom / zeroize | OS-random nonce and guarded explicitly owned secret buffers |

The existing pinned optional AEAD dependency is enabled by `private-input-proofs`.
No dependency version, default feature, Source profile, FHE/proof envelope or byte
cap changes. The lock file adds only this direct dependency edge.

## API and association

`SourceStateAuthority::new(Zeroizing<[u8;32]>)` consumes an externally custodied
high-entropy wrapping key. The wrapping key must be distinct from the Source key.
No key getter, Clone, Debug or serde exists; a password KDF or adjacent key file
is not selected. The caller must retain the authority independently of ciphertext.

`SourceStateIdentity::new(record_id32, Ckey32)` retains independent saved pins.
It rejects noncanonical Gold aliases. The record never supplies its own expected
identity. `EncryptedSourceState::from_bytes` checks exact canonical bounds only;
`as_bytes` returns ciphertext, not a verified or fresh Source capability.

`owner.backup_private_state(identity, fetched, authority)` and
`SourceOwner::restore_private_state(identity, fetched, authority, record)` take
the existing `FetchedSource`: independently pinned object and full ReadHeads,
plus the actual complete RawBundle already supplied in memory by the caller.
Neither method fetches anything. Both perform the real existing SourceOwner load:
full byte/root audit, actual AEAD decryption, complete index/TableId check, all
four original rows and exact Ckey comparison. Temporary loaded plaintext drops
before backup returns. Restore constructs a private candidate from the original
key and salt, calls the same load, and returns it only on success. It never calls
SourceOwner::new or resamples Ckey salt.

Ckey binds only database/domain/key/salt; it does NOT bind a current revision,
root or agreed head. Both complete112-byte heads and the independent object are
therefore separately authenticated. Object addresses also bind their original
nonce; load checks the supplied unchanged bundle, never regenerating that nonce.
The same existing DB/domain sealer is restored, not a head-restricted SQL token.
Per-query Copen and query/mask/encoding salts must still be freshly generated by
their original producers. No plaintext WHERE, mask or selected answer is saved.

## Exact new backup format

`DCSOSS01` version1 has public AD header368: magic8/version2/role1/reserved5,
record32, object32, dataHead112, indexHead112, canonical Ckey32, random XNonce24,
ciphertext length4, reserved4. Both head schemas/geometries are exact current N4
and their database/domain must agree. Every expected header is reconstructed from
caller pins before decryption, never adopted from the supplied record/bundle.

The encrypted104-byte payload is privateMagic8, AEAD key32, four canonical
little-endian u64 salt words32 and TableId32, followed by AEAD tag16. TableId stays
inside ciphertext. All exact lengths, reserved bytes, role, canonical heads,
Gold values and EOF reject before record allocation; private salt/table checks
precede candidate use. Source keys themselves have no invented zero restriction.
All explicit plaintext/key/salt buffers use Zeroizing. Caller copies, compiler
temporaries, native field/trace/allocator scratch are not promised erased.

This is a NEW owner backup format, not a modification of any proof profile.
The AEAD primitive is reused directly; BFV owner_state's private624-byte
setup/anchor/Key33 policy is neither copied nor generalized into a secret service.

## Executed owning tests and remaining work

Five new runtime tests use explicitly PUBLIC NONSECRET fixture keys/rows
and in-memory images only. They cover real seal/drop/restore/all-row/index load,
stable Ckey, fresh wrapping nonce, independent scope/master/key pin, tampering,
truncation/trailing/limits/cross-role rejection, genuine AEAD-authenticated
malformed private payloads, canonical salt boundaries and one actual existing
Core Source proof/self-verification after the original SourceOwner drops. Seven
compile-fail examples protect authority/record traits and Source secret fields.
No real-user key, filesystem store, OS vault or network is accessed by these cases.
The genuine Source test uses the typed producer's actual SDK self-verification;
it does not claim an additional standalone public Source-byte verifier.
