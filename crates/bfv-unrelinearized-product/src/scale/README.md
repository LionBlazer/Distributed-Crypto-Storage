# Exact public scaler certificates

This private library module checks the pinned fhe-math0.1.1 PowerBasis scaler for one closed N4096, Q2/P2 geometry. It is separate from the existing production BFV proof profiles. It provides neither a Source/Encoding proof nor a multiplication, SQL completeness, authorization, freshness, or consensus grant.

The parent supplies four independently bound input polynomials to Extend2To4 and three independently bound tensor-product polynomials to Scale4To2. Rows are basis-major, natural PowerBasis order, with all 4096 coefficient present. Extend copies both Q rows exactly. The down factor is 65537/(Q0*Q1). The fixed ordered P basis is generated by the pinned BFV builder's 62-bit prime rule. The parent must independently bind these exact rows to its public statement, intermediate product relation, original request/response bytes and output ciphertext. A caller-selected binding hash alone proves none of those associations.

Request::new(role, binding, rows) and Output::new(&request, rows) check full shape and canonical residues; rows() borrows those untrusted public values. evaluate(&request) is the prover: it performs the SDK-equivalent rounding and reduction divisions. verify_certificate(&request, &output, &certificate) is separate: it checks signed 256-bit linear equalities and bounded derived remainders. It never calls the SDK scaler, computes a quotient/remainder by division, executes an NTT/ciphertext product, or sees plaintext/keys. Successful scalar checks are deterministic arithmetic checks, not a new cryptographic proof system.

For the SDK-derived fixed constants T_i, signed theta_i, gamma_j and omega_ji, the quotient witnesses obey:

- S=sum(r_i*T_i);0<=S+2^126-v*2^127<2^127.
- E=sum(r_i*theta_i);w=biased_w-2^45;0<=E+2^126-w*2^127<2^127.
- A_j=sum(r_i*omega_ji)+w-v*gamma_j; k_j=biased_k_j-2^64; A_j-y_j=p_j*k_j, with canonical0<=y_j<p_j.

These intervals uniquely fix the same approximate Garner quotient and signed rounding used by this SDK, including exact-half ties toward positive infinity. They do not replace the SDK algorithm with ideal centered CRT rounding. The two roles have shift 127 and exact zero GammaTheta; the extension has zero theta, while the downscaler's P-input theta terms are zero. Public proof validation must retain the exact constructor constants, sign rules and all ordered basis parameters.

The maximum accepted input sum is below 2^63+2^31; all T_i<2^127. Thus S < 2^191. The fixed theta sum has absolute value < 2^157, so |w|<2^32. For each output prime, |k_j|<sum(r)+|w|/p+1<2^64. All computations and adversarial witnesses use checked I256 operations, and reject overflow. The implementation allows biased_w<2^46 and biased_k<2^66; the larger ranges do not add ambiguity because the exact intervals/equalities remain mandatory. Radix carries and the two remainders are not transmitted or trusted.

Each certificate is exactly 131,216 bytes: a 144-byte header followed by 4096 canonical 32-byte rows. The header binds magic/version, role, seven reserved zeros, parent binding32, the new scaler-profile SHA256, full input SHA256 and full output SHA256. A row is vLE64, biased_w LE46 in 6 bytes (top two bits zero), then two biased_k LE66 values in 9 bytes each (top six bits zero). Decode checks exact length/EOF, profile, reserved bytes and all ranges before returning metadata. Seven frames total 918,512 bytes, excluding the parent's inputs/outputs, product/PIT witnesses and outer headers. This is a byte bound, not a 500ms latency claim.

Direct dependencies are crate::geometry, the parent's Error/Result, ethnum's checked signed 256-bit integers, num-bigint/num-traits for immutable constructor constants, and SHA256 for metadata association. SDK fhe, fhe-math and ndarray are used only by tests. No Plonky3/LogUp/range-table/NTT dependencies remain in this module.

The tests reuse two actual SDK polynomial scalers and compare all basis rows/all 4096 positions for zeros, negative-one residues, asymmetric full-domain residues, and CRT half-boundary inputs. The codec, repaired final-output digest, every quotient, copied Q prefix, bindings, full-tail canonical residues and witness ranges have separate rejection examples. The five scaler tests passed as part of the 13-test owning suite recorded in [historical experiment validation](../../../../experiments/bfv-unrelinearized-certificate/VALIDATION.md). They establish arithmetic conformance on the stated cases, without certifying BFV noise/correctness probability or lattice security, and do not unblock the rejected oversized Stage35 STARK composition.


The reusable library now passed eighteen owning tests, including the actual
SDK midpoint contrast, plus strict Clippy and the real upper consumer. See the
[extraction validation](../../VALIDATION.md). For the arbitrary QP coefficient
`x=(Q0*Q1*P0*P1-1)/2`, the SDK output is `[1072594946,513385678]`, while
ideal centered rounding gives `[1097726,560282418]`. The integer certificate
correctly accepts the former. This is not a complete product counterexample:
its constrained canonical-Q2 depth-one tensor cannot reach that midpoint.
[MODEL.md](../../MODEL.md) records that deterministic distinction and the
remaining probabilistic/security assumptions.
