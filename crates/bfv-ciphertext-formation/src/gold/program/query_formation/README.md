# Fused query Formation backend

Fixed single-AIR mathematics for the complete Stmt96/mask/Cw/Cs/QueryCt
relation, behind the public [gold::query](../../query.rs) mathematical facade.
It is not registered in SQL, peer runtime or owner custody. The retained
13-field statement header is supplied independently by the upper family; this
module does not verify Word history or choose SQL semantics. Source/DATA/key
admission, current weighted head, product/result, locks, transport and
complete-query latency remain upper work. The private registry composition now
binds the exact original ordered pair, retained DATA Expected and original Word
header through this facade; it still grants no SQL or DATA admission.

The complete lower DATA Expected is retained and rebound with a distinct fused
protocol, full statement root and full header. Its original request, nonce,
canonical ciphertext, Cw/Cs contexts and roots are preserved. The protected
preparation owns the SAME final scaled W, actual SDK-secret opening and full
statement preimage, without private getters. A successful native receive proves
only these mathematical relations; no acceptance capability is serialized.

The v2 layout is H2048/MAIN416. It repacks all81920 original graph gates into
57 slots per row, then hashes Cw4112, Cs528 and Stmt96 in514+66+12 rows. All4096
complete S/E/K range groups still occupy every physical row. There are18
range-only tail rows. The full Cw stream is hashed once instead of twice, while
both roots and every original coefficient remain claimed. No crypto algorithm,
integer/noise bound or required coefficient is omitted.

Each low W coefficient is0 or16389; all3840 high coefficients are zero. Two bits
per row accumulate eight32-bit mask words in the exact reversed coefficient
order. One extra global node family connects those words to fields78..85 of the
complete statement hash. The original header13 and zero95 have explicit fixed
input constraints. A full local hash check alone cannot establish that lookup.
The original Cs packer, SAME-S graph, shared bounded E and exact K equations are
reused. All other statement fields and private salts enter the original sponge.

Direct dependencies are the original Gold graph/descriptor, shared range emitter,
guarded equation derivation/dense writer, existing Poseidon2 gadget and pinned
P3/hiding/bounded-codec libraries. The native assessment, public setup, prover,
canonical frame and receiver source is instantiated against two concrete closed
families by `program::dense_backend`; no runtime AIR/config callback is exposed.
Existing dense APIs keep their exact protocol/profile. This candidate has the
distinct DCSGQF02 namespace and closed PP708/PUBLIC32/original248/default83/AUX420
geometry, with eight quotient chunks and2490 actual batched openings.

ordered BASE/EXT/original/packed tuple and every1449984 PP field. Unconditional

The owning cases cover a genuine patterned SDK query, every reversed coefficient,
all mask-word endpoints, repaired statement/header hashes, a genuine false high-W
proof and a genuine unbalanced-mask lookup proof. Test-only negative trace
preparation bypasses honest mask checking exclusively to exercise the unchanged
native receiver; no public or production bypass exists. The
[validation record](VALIDATION.md) separates actual execution from remaining work.

`gold::query::Expected::checked` captures public metadata; it verifies no proof.
Its `core_expected()` supplies the rebound public binding for `data::Prepared`.
`query::Prepared::new` consumes that same guarded preparation and complete Stmt96,
checking the original captured binding before any proof. `query::prove` returns
unverified bytes; `query::verify` always bounds/decodes the distinct frame, rebuilds
public PP and calls the actual native verifier. Only then can it return the
move-only, privately constructed `query::VerifiedFormation`. There is no cast
to DATA/Word/Source admission, setup callback or format fallback. All fixtures,
attack trace writers and diagnostic snapshots remain test-only.

`gold::query::Verifier::new` independently derives public setup for one complete
original query before its proof arrives. It retains the immutable Expected/AIR,
resource/security assessment and verifier CommonData, then drops producer-only
PP storage and every setup configuration/RNG. `verify(bytes)` has no replacement
Expected/setup argument: every invocation binds the original frame, performs
bounded canonical decoding and executes the actual native verifier. Neither a
previous success nor failure is cached. Construction verifies no proof and grants
no Word/Source/current-head/SQL capability. The ordinary cold `verify` retains
its original header, prescreen and decode-before-PP rejection order. Its profile,
preprocessing pins and full equations are unchanged. The Query-owned internal
`receiving` module depends only on this fixed backend's prescreen/setup/codec;
no generic AIR, caller-supplied CommonData or cross-query cache is introduced.
Preparation cost still belongs to each new query's total latency.
